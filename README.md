# Human-Led AI Project Mastery

> **Learn to use AI to increase what you can accomplish without requiring yourself to understand less.**

Human-Led AI Project Mastery (HLAPM) is an open public learning project for people who want AI to accelerate meaningful work **without permanently surrendering the knowledge behind that work**.

The goal is not increasingly elaborate prompts. The goal is to become progressively better able to understand, direct, evaluate, verify, reproduce, adapt, diagnose, prompt for, deliver, teach, and systematize AI-assisted work.

## Before You Begin

AI can produce convincing but incorrect output, and successful AI-assisted work does not automatically prove personal mastery. Protect confidential information, verify consequential results, respect licensing and professional boundaries, and use assessment and challenge systems as learning tools rather than unquestionable credentials or punitive grading systems.

**Read [DISCLAIMER.md](DISCLAIMER.md) before adopting these workflows in professional, educational, or workplace settings.**

## Core Principle

> **AI should increase human capability without requiring human understanding to decrease.**

## Start Here

`Ask → Observe → Understand → Explain → Reproduce → Adapt → Diagnose → Verify → Prompt From Knowledge → Assess → Challenge → Independent Practice → Teach → Systematize`

AI can still perform difficult work. The purpose of this framework is to make important knowledge, assumptions, verification, and human responsibility increasingly visible rather than leaving them permanently hidden behind successful output.

## Live-Project Learning

Whenever practical, use something you already genuinely want to accomplish instead of creating disposable demonstration projects.

`Learn → Find Real Project Need → Practice → Perform Useful Task → Assess Demonstrated Ability → Apply It Under Greater Challenge → Integrate Result`

### Assessment

`[assessment]` asks:

> **What can you currently demonstrate through authentic project work?**

It measures observable human capability, records untested ability honestly, and tracks unresolved gaps as **learning debt**.

See [assessment/README.md](assessment/README.md).

### Challenge

`[challenge]` asks:

> **Can you convert demonstrated knowledge into dependable, finished work under realistic constraints?**

A full challenge requires two linked deliverables:

1. a learner-authored advanced prompt built from acquired knowledge;
2. a finished real-project product completed under a fair but strict deadline.

See [challenge/README.md](challenge/README.md).

## Keep These Separate

**Project progress:** Did the work get completed?

**Learning progress:** What can the learner now understand, explain, reproduce, adapt, diagnose, verify, prompt for, or teach?

**Workflow discipline:** Can the learner organize, estimate, prioritize, verify, and finish work reliably?

A gap in understanding is **learning debt**. A gap in reliable execution is **workflow-discipline debt**.

## Prompt Maturity

Prompt engineering should grow from subject knowledge rather than replace it.

- Early: “AI, do this for me.”
- Developing: “Teach me how while helping me perform it.”
- Advanced: provide the objective, current state, constraints, assumptions, dependencies, risks, acceptance criteria, verification, human responsibilities, and AI responsibilities intentionally.

A longer prompt is not automatically a better prompt. The goal is increasingly deliberate communication grounded in understanding.
