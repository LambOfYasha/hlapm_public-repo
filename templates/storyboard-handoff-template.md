# PROPOSED — Portable Storyboard Handoff Template

Status: PROPOSED reusable scaffold. Human/source review is required before production use.

Use this with the [generic preprep-to-production workflow](../workflows/generic-preprep-to-specialized-production.md). A storyboard is a source-linked plan; a generated image or clip is a candidate that needs its own review.

## Project intake

- Objective and requested deliverable:
- Source script/outline and exact revision:
- Authorized scope and audience:
- Scene/shot/panel ID convention:
- Current pass and selected appearance:
- Approved baseline and review evidence, or unapproved draft:
- Aspect ratio, dimensions, FPS, and timing basis; unknown values remain unknown:
- Actual reference files and the fields each controls:
- Missing sources, assets, and decisions:
- Output/recovery locations:

A six-panel sheet is one layout. A shot can need several panels to explain its key states. Preserve IDs when order or layout changes.

## Reference register

| Asset ID/version | Role | Actual attachment/location | Availability | Controls | Review state |
| --- | --- | --- | --- | --- | --- |
| Fill from source | Character/place/prop/etc. | Real supplied file or unresolved | Available/missing/placeholder | Specific identity/geometry/etc. | Unreviewed/reviewed with evidence |

A filename in a prompt does not transfer the file. Availability and design approval are separate. Use only the content allowed for the receiving service.

## Global brief

```text
PROJECT / SOURCE REVISION:
OBJECTIVE AND AUTHORIZED SCOPE:
CURRENT PASS / REQUESTED APPEARANCE:
SOURCE BASELINE / HUMAN REVIEW EVIDENCE:
SHARED CONSTRAINTS:
FRAME SETTINGS / TIMING BASIS:
REQUIRED SOURCES / REFERENCES / MISSING INPUTS:
```

Keep the global brief concise. The full edit overview belongs in the board. Later finishing notes stay inactive until their pass is selected.

## One active shot request

```text
ACTIVE SHOT: [ID / REVISION]. Execute this shot only.
Earlier/later information supplies continuity context, not extra shots to perform.

SOURCE PASSAGE AND EXACT DIALOGUE:
CURRENT PASS / SOURCE BASELINE:
PURPOSE / FRAMING / CAMERA:
BLOCKING / SCREEN DIRECTION:
ENTRY STATE / ACTION BEATS / EXIT STATE:
DURATION / FPS / TIMING EVIDENCE, OR ESTIMATE:
PANELS / KEY STATES:
ACTUAL ATTACHMENTS AND WHAT EACH CONTROLS:
PRESERVE / CHANGE / AVOID:
REQUESTED OUTPUT / RECEIVING TOOL CAPABILITY CHECK:
MISSING / UNRESOLVED:
```

Review camera/timing proposals separately from source facts. A cleanup/detail pass preserves the reviewed baseline unless a new revision explicitly changes it. A request cannot manufacture a supported control in the receiving tool.

## Neutral example

Invented source: a sealed parcel rests on a table; a hand places a plain marker beside it. No dialogue or artwork is supplied.

Make shot A the establishing view and shot B the placement action. An external request for A asks only for A. Record the missing table reference and any proposed duration rather than claiming an inspected asset or verified timing. If an earlier shot's composition changes, identify dependent outputs for review; preserve the old approved revision.

## Return and review record

- Request/attempt ID and input source/reference revisions:
- Tool/model/version and actual settings when available:
- Output files and content digests:
- Observed errors or unsupported controls:
- Source coverage, visual continuity, motion, and audio checks actually performed:
- Human review decision and exact reviewed revision:
- Changed fields and downstream outputs needing revision:
- Recovery copy and next bounded action:

Generated, reviewed, approved, and published are different states. Check actual rendered motion and sound before claiming animation readiness. A static board or timed slideshow does not verify character animation.

## Practice and evidence

Use a small authorized passage from your own project. Explain panel versus shot, mark source facts versus directing proposals, and prepare one self-contained shot request with the real allowed attachments. Diagnose one missing/stale reference and record how you would recover the previous revision.

Verify that the package can leave the original service, retains stable IDs and source/review versions, makes unsupported controls visible, and excludes private material from any public derivative. A prepared AI template is not proof that the learner can make these judgments independently.

Assessment bridge: demonstrate this bounded handoff in the actual project when assigned. Challenge bridge: only after that evidence, adapt it to a second compatible tool under explicit scope and acceptance criteria. Teach-back: explain the source, proposal, candidate, and approval boundaries. Learning debt includes real provider behavior, storage migrations, rendered continuity, accessibility, and sound synchronization not yet tested.
