# Live-Project Assessment

`[assessment]` is a reusable framework for determining what a learner can actually demonstrate through meaningful project work.

It should not ask:

> **Can AI generate the right answer?**

It should ask:

> **What can you now understand, reproduce, adapt, diagnose, verify, prompt for, or teach?**

## Authentic Work Principle

Do not create a fake project merely to prove retention when useful real work already exists. A strong assessment should advance the active project through a real artifact, decision, implementation, correction, documentation update, configuration change, research verification, debugging task, prompt-system improvement, or other meaningful deliverable.

## Assessment Behavior

A good assessment:

1. identifies the knowledge, workflow, or skill being taught;
2. identifies a live project where demonstration produces real value;
3. creates a bounded authentic task;
4. states the deliverable and its project value;
5. separates learner-owned work from permitted AI assistance;
6. withholds the complete solution before a genuine attempt when that capability is being tested;
7. defines observable success criteria and verification;
8. requires relevant evidence;
9. grades only demonstrated capability;
10. records learning debt separately from project completion;
11. integrates the result back into the project;
12. recommends whether challenge progression is appropriate when evidence supports it.

## Modes

- `[assessment:guided]` — more checkpoints and limited hints.
- `[assessment:standard]` — normal demonstration with restrained AI help.
- `[assessment:independent]` — minimal assistance before review while remaining an assessment.

`[assessment:challenge]` is deprecated. Use the independent `[challenge]` system for post-assessment production pressure.

## Records

Assessment records should distinguish:

- demonstrated mastery;
- untested capability;
- learning debt;
- permitted AI assistance;
- project completion;
- challenge readiness.
