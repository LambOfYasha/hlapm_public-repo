# PROPOSED — Session to Public Learning Artifact

**Status:** PROPOSED  
**Date:** 2026-08-21  
**Purpose:** Convert meaningful AI-assisted project work into safe, reusable public teaching material without exposing private project context or confusing AI output with learner mastery.

## Core idea

A completed work session may contain two kinds of value:

1. **private operational value** — exact decisions, implementation details, project context, internal provenance, private failures, and next steps;
2. **public educational value** — transferable concepts, reasoning patterns, verification methods, practice activities, and lessons that can help other learners.

The public artifact should be **derived from** the private work, not copied from it.

## Trigger

Use this workflow after a substantive AI-assisted session that produces a reusable concept, method, troubleshooting lesson, architecture pattern, workflow, prompt strategy, or project-management practice.

Do not force public conversion when the material is confidential, private, highly project-specific, unreleased, legally restricted, personally sensitive, or too dependent on private context to teach safely.

## Step 1 — Extract the transferable principle

Ask:

- What did the session teach that would still matter if all private names were removed?
- What decision pattern, workflow, failure mode, or reasoning process is reusable?
- What did the human need to understand rather than merely receive from AI?

Write the answer as a learner capability, not as a project recap.

Example:

Private result:

> The studio separated raw chat archives from canonical memory and added a promotion/retrieval layer.

Public lesson:

> Learners can distinguish raw episodic AI history from curated durable memory and design a provider-independent retrieval architecture.

## Step 2 — Sanitize the source

Remove or generalize:

- private project names when unnecessary;
- unreleased intellectual property;
- private canon/lore;
- credentials and secrets;
- confidential customer/client details;
- private personal information;
- internal repository paths that reveal protected structure;
- exact transcripts unless publication is explicitly permitted.

Use fictional or generic examples where needed.

## Step 3 — Preserve the reasoning

Do not sanitize so aggressively that the lesson becomes empty.

Preserve:

- the problem;
- the important tradeoff;
- the reasoning process;
- the failure or risk;
- the verification method;
- the transferable design rule.

## Step 4 — Convert into the HLAPM lesson progression

Map the concept into:

`Purpose → Outcomes → Vocabulary → Mental Model → Demonstration → Practice → Explain → Reproduce → Adapt → Diagnose → Verify → Prompt From Knowledge → Assess → Challenge → Teach → Systematize`

Not every artifact needs every phase in full, but complete lessons should normally support the progression.

## Step 5 — Separate AI work from learner evidence

Record:

### AI may assist with

- summarization;
- diagram suggestions;
- example generation;
- critique;
- comparison;
- implementation support;
- drafting teaching materials.

### Learner must demonstrate

- explanation;
- classification;
- reasoning;
- verification;
- reproduction;
- adaptation;
- diagnosis;
- teaching, when mastery is claimed.

A polished public lesson generated by AI is not itself proof that the learner understands the subject.

## Step 6 — Choose the public destination

Use the smallest appropriate artifact type.

| Public value | Destination |
|---|---|
| Complete teaching module | `docs/lessons/` |
| Repeatable human-led process | `workflows/` |
| Generalizable real-world evidence | `case-studies/` |
| Reusable record/form | `templates/` |
| Experimental teaching method | `labs/` |
| Learner capability demonstration | `assessment/` |
| Advanced post-assessment work | `challenge/` |
| Reusable prompting pattern | `prompts/` |

One private session may produce more than one public artifact, but do not create files merely to increase output volume.

## Step 7 — Build the Canva conversion map

For concepts suited to visual teaching, use a slide progression such as:

```text
1. Problem
2. Why it matters
3. Vocabulary
4. Mental model
5. Architecture/process
6. Guided demonstration
7. Weak vs strong practice
8. Learner practice
9. Failure/diagnosis
10. Verification
11. Prompt from knowledge
12. Assessment bridge
13. Challenge bridge
14. Teach-back
```

Each slide should have one teaching purpose.

Prefer diagrams, comparisons, flowcharts, annotated examples, repository trees, timelines, and process maps over decorative visuals.

## Step 8 — Record learning debt

Ask what remains untested.

Examples:

- learner understands the architecture but has not implemented it;
- learner can write the schema but has not handled migration;
- learner can use one provider but has not demonstrated portability;
- learner can explain privacy rules but has not built secret scanning.

Keep project completion separate from human mastery.

## Step 9 — Verify public safety

Before publication, verify:

- no secrets or credentials;
- no private learner data;
- no confidential client/org material;
- no unreleased private canon/IP;
- no unsupported professional or mastery claims;
- no copied private transcript that should remain private;
- examples remain accurate after generalization.

## Step 10 — Preserve the private/public relationship

When appropriate, the private repository may record that a public teaching derivative exists.

The public repository should not require access to the private source to understand the lesson.

Conceptually:

```text
Private operational lesson
        ↓ generalize / sanitize
Public HLAPM artifact
```

Not:

```text
Private source → public redacted dump
```

## Completion checkpoint

Because a conversation may end without an explicit closing message, prepare the conversion plan at each substantive completion point.

If work continues later:

- update the public teaching derivative only when the new material changes the lesson;
- avoid duplicating unchanged sections;
- preserve meaningful corrections and failure lessons.

## Suggested closeout format

### Transferable concept

[What others can learn.]

### Public-safe abstraction

[What must be generalized/sanitized.]

### HLAPM destination

[Lesson/workflow/case study/etc.]

### Canva map

[Slide sequence.]

### Practice

[Learner-owned task.]

### Verification

[How correctness is checked.]

### Assessment bridge

[Authentic capability demonstration.]

### Challenge bridge

[Harder real-project extension after assessment.]

### Learning debt

[What remains untested.]

## Success condition

The workflow succeeds when a learner can benefit from the public artifact without access to the private project, while the important reasoning, verification, and human-learning goals remain intact.
