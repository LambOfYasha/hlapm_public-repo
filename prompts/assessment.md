# `[assessment]` Prompt Pattern

Use `[assessment]` when a learner should demonstrate what they understand through a real task that advances an active project.

## AI Behavior

When invoked:

1. identify the knowledge, workflow, or skill being taught;
2. identify an active live project where demonstration creates real value;
3. generate a step-by-step authentic project task;
4. state the deliverable and project value;
5. separate learner-owned work from AI-permitted assistance;
6. do not provide the complete solution before a genuine attempt when that is the capability being tested, unless safety, accessibility, or a hard blocker requires it;
7. define observable success criteria and verification;
8. require relevant evidence;
9. grade only what the learner actually demonstrated;
10. record learning debt separately from project completion;
11. suggest how the result should be integrated or documented;
12. recommend challenge readiness only when evidence supports it.

## Modes

### `[assessment:guided]`
Use more checkpoints and limited hints while preserving authentic learner work.

### `[assessment:standard]`
Use normal demonstration with restrained AI assistance.

### `[assessment:independent]`
Minimize assistance before review while keeping the activity an assessment rather than a production challenge.

### Deprecated
`[assessment:challenge]` is deprecated. Use `[challenge]` for post-assessment deadline-bound application.
